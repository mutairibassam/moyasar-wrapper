# Status Sync & Cancel (Plan 5 of 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep locally-mirrored invoice statuses current after submission — a recurring, self-rescheduling `sync_invoices` job that polls Moyasar by metadata and records `paid`/`expired`/`canceled` on each item, plus on-demand "refresh now", invoice cancellation, and the read API the invoices explorer will consume.

**Architecture:** A `SyncEngine` (the `sync_invoices` job handler) lists local items whose Moyasar status is still open (`initiated`/`on_hold`) grouped by batch, pages `MoyasarClient.listByBatch(platformBatchId)`, and writes each item's `moyasarStatus` + `lastSyncedAt` from the returned invoice. The handler re-enqueues itself with a delay (self-rescheduling recurring job). "Refresh now" runs the same per-batch reconciliation synchronously via a route. Cancel calls a new `MoyasarClient.cancel` and records `canceled` with an audit entry. A read-only `InvoicesService` backs `GET /api/v1/invoices` (filters + pagination over the local mirror). Polling is the only mechanism that detects `expired`/`canceled` (Moyasar has no invoice webhooks); webhooks remain deferred.

**Tech Stack:** Bun ≥1.2, Hono 4, Drizzle ORM 0.45, Zod 4, PostgreSQL 17. No new runtime dependency.

**Plan roadmap:** Plan 5 of 6, stacked on `feature/auth` (Plans 2–4). Plan 6 (Next.js frontend + Docker/Caddy deployment) is last. **Deferred beyond this plan:** the inbound webhook receiver (enhancement once internet-exposed).

- **Cancel** (`PUT /invoices/:id/cancel`) is allowed only for an item whose `moyasarStatus` is `initiated` (still payable); admins and approvers only. Records audit `invoice.canceled`.
- **RBAC:** invoices read (`GET /invoices`) — any authenticated role; cancel — approver/admin; refresh-now — maker/approver/admin (anyone who can act on a batch); it is a read-through, not a mutation of platform state, but still requires the CSRF header as a POST.

```ts
  async fetchInvoice(id: string): Promise<MoyasarInvoice> {
    const res = await this.getWithRetry(`/invoices/${encodeURIComponent(id)}`, "GET");
    const parsed = moyasarInvoiceSchema.safeParse(await res.json().catch(() => null));
    if (!parsed.success) throw new MoyasarApiError("Unexpected Moyasar invoice shape", parsed.error?.flatten(), true);
    return parsed.data;
  }

  async cancel(id: string): Promise<MoyasarInvoice> {
    const res = await this.getWithRetry(`/invoices/${encodeURIComponent(id)}/cancel`, "PUT");
    const parsed = moyasarInvoiceSchema.safeParse(await res.json().catch(() => null));
    if (!parsed.success) throw new MoyasarApiError("Unexpected Moyasar cancel shape", parsed.error?.flatten(), true);
    return parsed.data;
  }

  /** Retrying request for idempotent calls (GET, and cancel which is idempotent). Throws MoyasarApiError on a non-2xx that isn't retryable or when retries are exhausted. */
  private async getWithRetry(path: string, method: "GET" | "PUT"): Promise<Response> {
    let attempt = 0;
    for (;;) {
      let res: Response;
      try {
        res = await this.raw(path, { method });
      } catch (e) {
        if (attempt++ >= this.maxRetries) throw new MoyasarApiError(`Moyasar ${method} ${path} failed: ${String(e)}`, undefined, true);
        await this.backoff(attempt);
        continue;
      }
      if (res.ok) return res;
      if ((res.status === 429 || res.status >= 500) && attempt++ < this.maxRetries) {
        await this.backoff(attempt);
        continue;
      }
      const body = await res.json().catch(() => ({}));
      throw new MoyasarApiError(`Moyasar ${method} ${path} ${res.status}`, body, res.status >= 500);
    }
  }
```

```ts
  async listOpenSubmitted(): Promise<ItemRow[]> {
    return this.db
      .select()
      .from(invoiceItems)
      .where(and(isNotNull(invoiceItems.moyasarInvoiceId), inArray(invoiceItems.moyasarStatus, ["initiated", "on_hold"])));
  }

  async syncStatus(itemId: string, moyasarStatus: NonNullable<ItemRow["moyasarStatus"]>): Promise<void> {
    await this.db
      .update(invoiceItems)
      .set({ moyasarStatus, lastSyncedAt: new Date(), updatedAt: new Date() })
      .where(eq(invoiceItems.id, itemId));
  }

  async findByMoyasarInvoiceId(moyasarInvoiceId: string): Promise<ItemRow | null> {
    const [row] = await this.db.select().from(invoiceItems).where(eq(invoiceItems.moyasarInvoiceId, moyasarInvoiceId)).limit(1);
    return row ?? null;
  }

  async queryInvoices(opts: InvoiceQuery): Promise<{ items: ItemRow[]; total: number }> {
    const filters = [
      isNotNull(invoiceItems.moyasarInvoiceId),
      opts.moyasarStatus ? eq(invoiceItems.moyasarStatus, opts.moyasarStatus) : undefined,
      opts.batchId ? eq(invoiceItems.batchId, opts.batchId) : undefined,
      opts.createdAfter ? gte(invoiceItems.createdAt, opts.createdAfter) : undefined,
      opts.createdBefore ? lte(invoiceItems.createdAt, opts.createdBefore) : undefined,
    ].filter((f): f is NonNullable<typeof f> => f !== undefined);
    const where = and(...filters);
    const items = await this.db
      .select()
      .from(invoiceItems)
      .where(where)
      .orderBy(desc(invoiceItems.createdAt))
      .limit(opts.perPage)
      .offset((opts.page - 1) * opts.perPage);
    const [row] = await this.db.select({ value: count() }).from(invoiceItems).where(where);
    return { items, total: row?.value ?? 0 };
  }
```

### Task 3: Sync engine (`sync_invoices` handler) + reconciliation

**Files:**
- Create: `apps/api/src/modules/moyasar/sync-engine.ts`
- Test: `apps/api/test/moyasar/sync-engine.test.ts`

**Interfaces:**
- Consumes: `Repositories` (`items`, `batches`); a `SyncClient` interface `{ listByBatch(id, page): Promise<{ invoices: MoyasarInvoice[]; nextPage: number | null }> }` (the real `MoyasarClient` satisfies it, and the submission engine's `SubmissionClient` already declares `listByBatch` — reuse or declare a minimal one here).
- Produces:
  - `class SyncEngine` constructed with `{ repos: Repositories; client: SyncClient }`, method `syncOpenInvoices(): Promise<{ scanned: number; updated: number }>`.
  - `syncBatch(batchId: string): Promise<{ scanned: number; updated: number }>` — the per-batch reconciliation used by "refresh now" (Task 4).

**Algorithm (`syncOpenInvoices`):**
1. `const open = await repos.items.listOpenSubmitted()`. Group the open items by `batchId`.
2. For each batch id: call `syncBatch(batchId)` (below), accumulate counts.
3. Return `{ scanned, updated }`.

**Algorithm (`syncBatch`):**
1. Page `client.listByBatch(batchId, page)` (start page 1, follow `nextPage`, bounded to a max page count like the submission engine — reuse the same guard style: cap pages and require `nextPage` to strictly increase).
2. Build a map from `metadata.platform_item_id` → the invoice's `status` for every returned invoice.
3. For each local OPEN item of this batch (reload via `listOpenSubmitted` filtered to the batch, or accept the caller's slice), look up its id in the map. If found and the returned status differs from the item's current `moyasarStatus` AND the returned status is a valid `moyasar_invoice_status` enum value, `await repos.items.syncStatus(item.id, status)`; count it updated. If the returned status is not a recognized enum value, skip it (do not write) and continue.
4. `scanned` = number of open items considered; `updated` = number whose status changed.

Never touch the item's `status` column or the batch's `status`. If `listByBatch` throws, let it propagate (the job runner records the failure and retries).

```ts
  async enqueueIn(type: "submit_batch" | "sync_invoices", payload: Record<string, unknown>, delayMs: number): Promise<JobRow> {
    const [row] = await this.db
      .insert(jobs)
      .values({ type, payload, runAt: sql`now() + (${delayMs} || ' milliseconds')::interval` })
      .returning();
    return row!;
  }

  async hasPending(type: "submit_batch" | "sync_invoices"): Promise<boolean> {
    const [row] = await this.db
      .select({ value: count() })
      .from(jobs)
      .where(and(eq(jobs.type, type), inArray(jobs.status, ["pending", "running"])));
    return (row?.value ?? 0) > 0;
  }
```
